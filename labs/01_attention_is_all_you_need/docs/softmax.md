# Softmax — เข้าใจจากศูนย์

> **คำตอบสั้นที่สุด:** softmax คือการแปลง "คะแนนดิบ" ชุดหนึ่ง ให้กลายเป็น "สัดส่วน" ที่รวมกันได้ 100%
> โดยทำแค่สองอย่าง — **ยกกำลัง `e` แล้วหารด้วยผลรวม**

เอกสารนี้แยกออกมาเพราะ softmax เป็นชิ้นส่วนที่ถ้าเข้าใจไม่ชัด จะทำให้ส่วนอื่นของ Attention คลุมเครือไปหมด
โดยเฉพาะเรื่อง `1/√d_k` (ดู [`paper-notes.md`](paper-notes.md) หัวข้อ 3)

---

## 1. เริ่มจากปัญหาก่อน

Attention คำนวณ "คะแนนความเข้ากัน" ระหว่าง query กับแต่ละ key ออกมาได้ เช่น `[2.0, 0.0, 1.0]`
แต่คะแนนดิบแบบนี้**เอาไปใช้เป็นน้ำหนักตรง ๆ ไม่ได้**:

- คะแนนเป็นค่าอะไรก็ได้ — **ติดลบก็ได้** (น้ำหนัก `-3` แปลว่าอะไร?)
- คะแนน**ไม่รวมกันเป็น 1** — ถ้าเอาไปคูณ `V` แล้วบวกกัน ผลลัพธ์จะพองหรือหดตามขนาดคะแนน
  ไม่ใช่ "ค่าเฉลี่ยถ่วงน้ำหนัก" อีกต่อไป

**เปรียบเทียบ:** ลองนึกว่าเรามี "ความสนใจ" อยู่ 100% ต้องแบ่งให้กับ token ทุกตัวในประโยค
คะแนนดิบบอกแค่ว่า "ตัวไหนน่าสนใจกว่าตัวไหน" แต่ไม่ได้บอกว่า **แบ่งให้ตัวละกี่เปอร์เซ็นต์**
งานของ softmax คือแปลงอันดับความน่าสนใจ → เปอร์เซ็นต์ที่รวมกันได้ 100% พอดี

---

## 2. เริ่มที่ตัวอย่างเล็กที่สุด — แค่ 2 ตัวเลข

ก่อนไปเคสจริง ลองดูกรณีง่ายสุดก่อน:

```text
softmax([0.0, 0.0]) = [0.500, 0.500]   ← คะแนนเท่ากัน → แบ่งเท่ากัน
softmax([1.0, 0.0]) = [0.731, 0.269]   ← ตัวแรกนำอยู่ 1 คะแนน
softmax([2.0, 0.0]) = [0.881, 0.119]   ← นำอยู่ 2 คะแนน ยิ่งทิ้งห่าง
softmax([3.0, 0.0]) = [0.953, 0.047]   ← นำอยู่ 3 คะแนน เกือบกินรวบ
```

สังเกต 2 อย่าง:

1. ผลลัพธ์**รวมกันได้ 1 เสมอ** (0.731 + 0.269 = 1.000)
2. **ยิ่งคะแนนห่างกันมาก ยิ่งเทน้ำหนักไปทางผู้ชนะ** — แต่ผู้แพ้ไม่เคยเป็น 0 สนิท

---

## 3. ทำงานยังไง — แค่ 3 ขั้น

ใช้ตัวอย่างจริงจากแล็บ `[2.0, 0.0, 1.0]`:

```text
ขั้น 0  คะแนนดิบ      : [ 2.000,  0.000,  1.000 ]
          ↓  ขั้น 1: ใส่ exp() ทุกตัว  → ทำให้เป็นบวกทั้งหมด
ขั้น 1  exp(คะแนน)    : [ 7.389,  1.000,  2.718 ]
          ↓  ขั้น 2: บวกรวมกัน
ขั้น 2  ผลรวม         :   11.107
          ↓  ขั้น 3: หารทุกตัวด้วยผลรวม → บังคับให้รวมกันเป็น 1
ขั้น 3  ผลลัพธ์       : [ 0.665,  0.090,  0.245 ]   (รวม = 1.000 ✓)
```

เห็นภาพเป็นแท่ง:

```text
คะแนน 2.0  →  66.5%  |#################################
คะแนน 1.0  →  24.5%  |############
คะแนน 0.0  →   9.0%  |#####
```

**จบแล้วครับ softmax คือแค่นี้จริง ๆ** ตัวที่คะแนนสูงกว่าได้น้ำหนักมากกว่า แต่ตัวอื่นยังมีส่วนร่วมอยู่

---

## 4. ทำไมต้องใช้ `exp()` ไม่ใช่วิธีอื่น

| เหตุผล | อธิบาย |
|---|---|
| ทำให้เป็นบวกเสมอ | `exp(x) > 0` ทุกค่า แม้ `x` ติดลบ (`exp(-5) = 0.0067`) |
| ไม่สลับลำดับ | `exp` เป็นฟังก์ชันเพิ่มเสมอ — คะแนนมากกว่า ได้น้ำหนักมากกว่าเสมอ |
| หา gradient ได้ทุกจุด | เส้นเรียบ ไม่มีหักมุม → backpropagation ทำงานได้ |
| ผลต่างคงที่ = อัตราส่วนคงที่ | คะแนนต่างกัน 1 หน่วย → น้ำหนักต่างกัน `e ≈ 2.72` เท่า **เสมอ** |

ข้อสุดท้ายลองเช็คดูได้:

```text
softmax([1, 0]) → 0.731 / 0.269 = 2.718
softmax([5, 4]) → อัตราส่วนก็ยัง = 2.718   ← ต่างกัน 1 คะแนนเหมือนกัน
```

---

## 5. คุณสมบัติที่ 1 — บวกค่าคงที่เข้าไปทุกตัว ผลลัพธ์ไม่เปลี่ยน

```text
softmax([  2,   0,   1]) = [0.6652, 0.0900, 0.2447]
softmax([102, 100, 101]) = [0.6652, 0.0900, 0.2447]   ← เหมือนกันเป๊ะ
softmax([ -1,  -3,  -2]) = [0.6652, 0.0900, 0.2447]   ← ติดลบก็ยังเหมือนเดิม
```

ทั้งสามบรรทัดคะแนน**ห่างกันเท่ากัน** (`2,0,1` กับ `102,100,101` กับ `-1,-3,-2` ต่างกันแค่เลื่อนทั้งชุด)

> **softmax สนใจแค่ "ผลต่าง" ระหว่างคะแนน ไม่สนค่าสัมบูรณ์**

**ใช้ประโยชน์จริง:** นี่คือเหตุผลที่โค้ดในแล็บเขียน `scores - max(scores)` ก่อนเข้า `exp`
เพราะลบค่าคงที่ออกได้โดยผลลัพธ์ไม่เปลี่ยน แต่กัน `exp` ไม่ให้ค่าระเบิด
(`exp(1000)` = overflow ค่าล้น แต่ `exp(0)` = 1 สบาย ๆ)

---

## 6. คุณสมบัติที่ 2 — **คูณ** ด้วยค่าคงที่ ผลลัพธ์เปลี่ยนมหาศาล ⭐

หัวข้อนี้สำคัญที่สุด เพราะมันคือเหตุผลทั้งหมดของ `1/√d_k`:

```text
คะแนน × 0.1  = [ 0.2, 0.0,  0.1]  →  [0.367, 0.301, 0.332]   เกือบเท่ากันหมด (แบนราบ)
คะแนน × 1    = [ 2.0, 0.0,  1.0]  →  [0.665, 0.090, 0.245]   พอดี
คะแนน × 5    = [10.0, 0.0,  5.0]  →  [0.993, 0.000, 0.007]   เกือบเลือกตัวเดียว
คะแนน × 20   = [40.0, 0.0, 20.0]  →  [1.000, 0.000, 0.000]   เลือกตัวเดียวสนิท
```

**ทั้ง 4 บรรทัดมีลำดับความสำคัญเหมือนกันทุกประการ** (ตัวแรกมากสุดเสมอ) แต่ "ความคม" ต่างกันสุดขั้ว
— จากแทบแบ่งเท่ากัน ไปจนถึงกินรวบ

**เชื่อมกลับไปหา `1/√d_k`:** เมื่อ `d_k` ใหญ่ขึ้น คะแนนดิบ `q·k` จะกระจายกว้างขึ้นเองโดยอัตโนมัติ
(variance = `d_k` — พิสูจน์แล้วใน [`../notebooks/03_experiment.ipynb`](../notebooks/03_experiment.ipynb))
เหมือนถูก "คูณ" ให้ใหญ่ขึ้นโดยที่เราไม่ได้ตั้งใจ softmax เลยคมเกินไป
การหารด้วย `√d_k` **ไม่ได้เปลี่ยนว่าใครชนะ** แค่ดึงสเกลกลับมาให้ความคมพอดี

---

## 7. ทำไมชื่อ "**soft**max"

```text
argmax([2, 0, 1])  = [1, 0, 0]              ← "hard" เลือกตัวเดียว ที่เหลือทิ้งหมด
softmax([2, 0, 1]) = [0.665, 0.090, 0.245]  ← "soft" ทุกตัวมีส่วนร่วมตามสัดส่วน
```

**ทำไมต้อง soft?** เพราะ `argmax` เป็นฟังก์ชันขั้นบันได — ขยับ input นิดหน่อย output ไม่ขยับเลย
แปลว่า **gradient เป็น 0 ทุกจุด** โมเดลจึงเรียนรู้ไม่ได้เลย

ส่วน softmax ขยับ input นิดเดียว output ขยับตามทันที → มี gradient ให้ backpropagation ใช้เรียนรู้

---

## 8. ด้านมืด — Saturation (ทำไมคมเกินไปถึงไม่ดี)

gradient ของ softmax แปรตาม `p × (1-p)` โดย `p` คือน้ำหนักที่ออกมา:

| `p` (ความมั่นใจ) | `p × (1-p)` | ความหมาย |
|---|---|---|
| 0.5 | 0.250 | gradient เต็มที่ เรียนรู้ได้ดี |
| 0.9 | 0.090 | เริ่มช้าลง |
| 0.99 | 0.0099 | ช้ามาก |
| 0.999 | 0.000999 | แทบหยุดเรียนรู้ |

พอ softmax คมมาก (`p → 1`) **gradient แทบหายไป** โมเดลหยุดเรียนรู้ตรงจุดนั้น
นี่คือสิ่งที่เรียกว่า **saturated** และเป็นสิ่งที่ `1/√d_k` ป้องกันไว้

## 9. ลองเล่นเอง

วางโค้ดนี้ใน notebook หรือ Python ปกติได้เลย (ใช้แค่ `math` ไม่ต้องลง library):

```python
import math

def softmax(xs):
    m = max(xs)                                  # ลบ max กัน overflow (หัวข้อ 5)
    exps = [math.exp(x - m) for x in xs]
    total = sum(exps)
    return [e / total for e in exps]

# ลองเปลี่ยนตัวเลขดู แล้วสังเกตว่าผลลัพธ์เปลี่ยนยังไง
print(softmax([2.0, 0.0, 1.0]))       # พื้นฐาน
print(softmax([20.0, 0.0, 10.0]))     # คูณ 10 -> คมขึ้นมาก
print(softmax([0.2, 0.0, 0.1]))       # หาร 10 -> แบนราบ
print(softmax([2.0, 2.0, 2.0]))       # เท่ากันหมด -> แบ่งเท่ากัน
```

**คำถามชวนคิด:** ถ้าคะแนนทุกตัวเท่ากันหมด softmax จะให้ผลอะไร? แล้วมันสมเหตุสมผลไหม
ในบริบทของ attention? (เฉลย: แบ่งเท่ากันทุกตัว — แปลว่า "ไม่รู้จะสนใจตัวไหนเป็นพิเศษ" ซึ่งถูกต้อง)

## สรุป

> softmax = แปลงคะแนนดิบเป็นสัดส่วนที่รวมกันได้ 1 โดย `exp` แล้วหารผลรวม
>
> - สนใจแค่ **ผลต่าง** ของคะแนน ไม่สนค่าสัมบูรณ์ (บวกค่าคงที่ = ไม่เปลี่ยน)
> - **ขนาด** ของผลต่างเป็นตัวคุมว่าน้ำหนักจะ **คมหรือแบน** (คูณค่าคงที่ = เปลี่ยนมหาศาล)
> - คมเกินไป = gradient หาย = เรียนรู้ไม่ได้ → จึงต้องมี `1/√d_k`
